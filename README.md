# voice-reply

Claude Code の返事を声で読み上げるプラグインです。OS 標準の声ですぐに使えます（Mac は `say`、Windows は SAPI の声）。[AivisSpeech Engine](https://github.com/Aivis-Project/AivisSpeech-Engine) を動かしておけば、その自然な声で読みます。

返事の最後に、耳で聞いて分かる短い要約（`<speak>〜</speak>`）を Claude に付けさせ、その要約を読み上げます。

## できること

- **返事の読み上げ**：Claude が返事を書き終えると、その返事を読み上げます。読み上げはバックグラウンドで動くので、読んでいる間も次の操作ができます
- **要約だけを読む**：返事の一番最後にある `<speak>〜</speak>` の中身だけを読みます。要約の書き方の指示は、このプラグインがセッションの始めに Claude に渡します
- **AivisSpeech の声**：AivisSpeech Engine が動いていれば、その声で読みます。動いていなければ、OS 標準の声で読みます（「AivisSpeech の声で読む」を参照）
- **タブごとの交通整理**：同じタブで次の返事が来たら、今の読み上げを止めて新しい返事に差し替えます。別のタブの返事は、今の読み上げが終わるまで順番を待ちます（声が重なりません）
- **オン・オフ**：`/voice-reply:toggle` で読み上げを止めたり、再開したりできます

## 必要なもの

| もの | 内容 |
| :- | :- |
| Claude Code | v2.1.332 で動作を確認しています |
| Node.js | 18 以上（Node に標準で入っている `fetch` を使うため）。`node` コマンドが PATH から使えること。npm パッケージは使いません |
| Mac の声 | `say` コマンド（macOS に標準で入っています）と、日本語の声「Kyoko」。Kyoko が入っていないときは、システム設定の「アクセシビリティ」→「読み上げコンテンツ」で追加するか、`VOICE_REPLY_MAC_VOICE` で入っている声を指定してください |
| Windows の声 | Windows PowerShell 5.1（Windows に標準で入っています）と、日本語の声「Microsoft Haruka Desktop」。Haruka が入っていないときは、入っている日本語の女性の声、なければ日本語の声に自動で切り替えます。`VOICE_REPLY_WIN_VOICE` で、入っているほかの声を指定することもできます |
| AivisSpeech の声（使うときだけ） | AivisSpeech Engine を自分で起動しておくこと（「AivisSpeech の声で読む」を参照）。音は、Mac は `afplay`、Windows は Windows PowerShell 5.1 で鳴らします（どちらも OS に標準で入っています） |

Mac と Windows 以外の OS では、読み上げは動きません。要約の指示も渡さず、何もせずに終わります。

## 入れ方

Claude Code のセッションで、次の2つを順に実行します。

```text
/plugin marketplace add mg1986jp/voice-reply
/plugin install voice-reply@mg1986jp
```

- 1行目で、このリポジトリをマーケットプレイス `mg1986jp` として登録します
- 2行目でプラグインの画面が開くので、インストールします。画面を閉じると、Claude Code がプラグインを読み込み直します
- **実行結果**：次の返事から読み上げが始まります
- **要約の指示について**：要約の指示はセッションの始めに渡すため、インストールした時点で開いていたセッションには届いていないことがあります。届いていないセッションでは、返事の全文（Markdown の記号を除いたもの）を読みます。要約を読ませたいときは、`/clear` を実行するか、新しいセッションを始めてください

## 使い方

入れたあとは、何もしなくても返事ごとに読み上げます。読み上げる文章は次のように決まります。

1. 最初に「（作業フォルダの名前）の作業です。」と読みます。どのタブの返事かを聞き分けるためです
2. 返事の一番最後に `<speak>〜</speak>` があれば、その中身を読みます
3. なければ、返事の全文を読みます。Markdown の記号は取り除き、コードは「コードは省略します。」、URL は「URLは省略します」と読みます

## AivisSpeech の声で読む

[AivisSpeech Engine](https://github.com/Aivis-Project/AivisSpeech-Engine) は、AI で自然な日本語の声を作るソフトウェアです。このプラグインは、エンジンも声のモデルも同梱しません。使うときは、エンジンを自分で起動しておきます。

### エンジンを起動する

次のどちらかで起動します。どちらも、エンジンは `http://127.0.0.1:10101` で待ち受けます。

| 起動のしかた | 内容 |
| :- | :- |
| AivisSpeech（アプリ）を開いておく | [AivisSpeech](https://github.com/Aivis-Project/AivisSpeech/releases) を開いている間は、アプリに入っているエンジンも動いています |
| エンジンだけを起動する | [AivisSpeech Engine の Release](https://github.com/Aivis-Project/AivisSpeech-Engine/releases) から OS に合うファイル（7z 形式）を取ってきて展開し、`run.exe`（Windows）か `run`（Mac）を起動します。Windows では、標準で入っている `tar -xf <ファイル名>` で展開できます |

- **初めて起動したとき**：初期の声のモデル（まお・コハク）と、音声を作るのに使う BERT のモデル、合わせて約 1.1 GiB を自動でダウンロードします。起動が終わるまで数分かかります（Windows で測ると約2分半）。2回目からはダウンロードせず、数秒〜数十秒で起動します
- **起動を待つ間**：エンジンが応答するまでの返事は、OS の声で読みます
- **エンジンだけを起動するとき**：`--disable_sentry` を付けると、エンジンのエラーログを外部のサービス（Sentry）に送らなくなります（例：`run.exe --disable_sentry`）。ポートを変えるときは `--port` を付け、`VOICE_REPLY_AIVIS_URL` も合わせます

### どの声で読むか

読み上げのたびに、順番が来てから、エンジンが応答するかを問い合わせます（最大1.5秒待ちます）。

| エンジンの様子 | 読む声 |
| :- | :- |
| 応答した | AivisSpeech の声 |
| 応答しない（起動していない、起動の途中、ポートが違う など） | OS の声 |
| 応答したが、1文目の音を鳴らし始める前に失敗した（音声を作れない、音を鳴らす処理を起動できない、WAV を読み込めない など） | OS の声で、最初から全部読みます（まだ何も聞こえていないため） |
| 音を鳴らし始めたあとに失敗した（1文目を鳴らしている途中や、2文目から） | そこでやめます。次の文を作るのに失敗したときは、鳴っている文は最後まで鳴らします（OS の声で読み直すと、同じところを2回聞くことになるため） |

`VOICE_REPLY_ENGINE` で、どちらかの声に決めておくこともできます（「声と速さの変え方」を参照）。

### 読み方

- **文ごとに作って順に鳴らす**：句点（。）・感嘆符・疑問符と改行で文に分け、100文字より長い文は読点（、）でさらに分けます。1文を鳴らしている間に、次の文の音声を作ります。最初の音は、読み上げを始めてから1秒ほどで鳴ります（Windows、Core i7-14650HX で測った値。音声は CPU で作るので、遅い PC ではもっとかかります）
- **声**：初期は「まお（ノーマル）」です。エンジンに入っていなければ、入っている声の最初のスタイルで読みます
- **速さ**：初期は speedScale 1.4 です。1秒に約8文字で、OS の声の初期の速さとほぼ同じです
- **音の一時ファイル**：音声は WAV の一時ファイルにして鳴らし、鳴らし終えたらすぐに消します。置き場所は、プラグインのデータフォルダの `audio/` です

### エンジンのデータと、読んだ文章の記録

- **データの大きさ**：エンジンは、声のモデルなどで約 1.1 GiB を使います。置き場所は変えられません（Windows は `%APPDATA%\AivisSpeech-Engine`、Mac は `~/Library/Application Support/AivisSpeech-Engine`）。このプラグインをアンインストールしても消えません
- **読んだ文章がログに残る**：エンジンは、受け取った文章を、データフォルダの `Logs` の2つのファイルに書きます。`AivisSpeech-Engine.log` には `Text:` としてそのまま、`AivisSpeech-Engine-Access.log` には問い合わせの URL として（URL エンコードされた形で）残ります。ログはエンジンを起動するたびに作り直されるので、残るのは、その回に起動してから読んだ文章です。返事の要約に人に見せたくないことが入る場合は気をつけてください
- **文章を送る先**：このプラグインは、読む文章を `VOICE_REPLY_AIVIS_URL` のエンジン（初期値は自分の PC の `http://127.0.0.1:10101`）にだけ送ります。ほかのパソコンのエンジンを指定すると、読む文章がそのパソコンに送られます
- **メモリ**：エンジンは、動いている間 1〜2 GiB のメモリを使います

## オン・オフ

| コマンド | 実行結果 |
| :- | :- |
| `/voice-reply:toggle` | 今と逆にします（オンならオフ、オフならオン） |
| `/voice-reply:toggle on` | オンにします |
| `/voice-reply:toggle off` | オフにします |

- **オフのとき**：返事を読み上げません。新しいセッションを始めても、要約の指示を渡しません
- **切り替えたとき**：そのセッションの Claude にも、すぐに伝わります。オンにしたときは要約の指示を、オフにしたときは「要約は不要」と伝えます
- **状態の保存**：状態はすべてのタブで共通で、Claude Code を終了しても残ります。ほかのタブで開いているセッションの Claude には切り替えたことが伝わらないので、そのタブでは要約が付き続けたり（読み上げはされません）、付かなかったりします
- **読んでいる途中でオフにした場合**：その読み上げは最後まで続きます。次の返事から読み上げなくなります
- **順番待ちの読み上げ**：別のタブの読み上げが終わるのを待っている返事は、オフにすると読まれません。順番が来たときに、オンかオフかを確かめ直すためです

## 声と速さの変え方

環境変数で変えます。`~/.claude/settings.json` の `env` に書いておくと、いつも同じ設定で動きます。

```json
{
  "env": {
    "VOICE_REPLY_AIVIS_STYLE": "888753762",
    "VOICE_REPLY_AIVIS_SPEED": "1.2",
    "VOICE_REPLY_WIN_RATE": "5"
  }
}
```

| 環境変数 | 対象 | 内容 | 初期値 |
| :- | :- | :- | :- |
| `VOICE_REPLY_ENGINE` | すべて | どの声で読むか。`auto`：エンジンが応答すれば AivisSpeech、しなければ OS の声。`aivisspeech`：いつも AivisSpeech（エンジンが応答しなくても OS の声に切り替えず、読みません）。`os`：いつも OS の声 | `auto` |
| `VOICE_REPLY_AIVIS_STYLE` | AivisSpeech | 声のスタイル ID（整数）。下の表か、エンジンの `GET /speakers` で確かめます | `888753760`（まお／ノーマル） |
| `VOICE_REPLY_AIVIS_SPEED` | AivisSpeech | 速さ（speedScale）。`0.5`〜`2.0` の数。`1.0` がモデルの標準の速さです | `1.4` |
| `VOICE_REPLY_AIVIS_URL` | AivisSpeech | エンジンの URL。エンジンを `--port` でほかのポートにしたときに変えます | `http://127.0.0.1:10101` |
| `VOICE_REPLY_MAC_VOICE` | Mac の声 | 声の名前 | `Kyoko` |
| `VOICE_REPLY_MAC_RATE` | Mac の声 | 速さ。`say -r` に渡す値（1分あたりの語数）で、正の整数 | `260` |
| `VOICE_REPLY_WIN_VOICE` | Windows の声 | 声の名前。入っていなければ、入っている日本語の女性の声、なければ日本語の声に切り替えます | `Microsoft Haruka Desktop` |
| `VOICE_REPLY_WIN_RATE` | Windows の声 | 速さ。System.Speech の Rate で、`-10`〜`10` の整数。`0` が標準の速さで、1増えるごとに約1.12倍になります | `3`（標準の約1.4倍） |

初期の声のスタイル ID です（エンジンを初めて起動したときに入る声）。

| 声 | スタイル（スタイル ID） |
| :- | :- |
| まお | ノーマル（`888753760`）、ふつー（`888753761`）、あまあま（`888753762`）、おちつき（`888753763`）、からかい（`888753764`）、せつなめ（`888753765`） |
| コハク | ノーマル（`1878365376`）、あまあま（`1878365377`）、せつなめ（`1878365378`）、ねむたい（`1878365379`） |

- **決まりに合わない値**：範囲外の数や、数字でない文字を書いたときは、初期値で読みます。Mac と Windows の声の速さは、小数を切り捨てて使います（`250.7` は `250`）。AivisSpeech の速さは小数のまま使います
- **エンジンに入っていないスタイル ID**：エンジンに入っている声の、最初のスタイルで読みます
- **反映されるタイミング**：`settings.json` を変えたら、Claude Code を起動し直すと確実に反映されます

### 古い名前からの切り替え

0.2.0 で、環境変数の名前を `CLAUDE_SAY_*` から `VOICE_REPLY_*` に変えました。古い名前は読みません（書いたままにすると、初期値で読みます）。

| 古い名前（0.1.x） | 新しい名前（0.2.0 から） |
| :- | :- |
| `CLAUDE_SAY_VOICE` | Mac なら `VOICE_REPLY_MAC_VOICE`、Windows なら `VOICE_REPLY_WIN_VOICE`（古い名前は Mac と Windows で共通でしたが、新しい名前は OS ごとに分かれています） |
| `CLAUDE_SAY_RATE` | `VOICE_REPLY_MAC_RATE` |
| `CLAUDE_SAY_WIN_RATE` | `VOICE_REPLY_WIN_RATE` |

1. `~/.claude/settings.json` の `env` で、古い名前を新しい名前に書き換えます。値はそのまま使えます。Mac と Windows の両方で同じ `settings.json` を使っていて `CLAUDE_SAY_VOICE` を書いていたときは、`VOICE_REPLY_MAC_VOICE` と `VOICE_REPLY_WIN_VOICE` に、それぞれの OS の声の名前を書きます。シェルの設定ファイルなど、ほかの場所で環境変数を設定しているときは、そちらも書き換えます
2. Claude Code を起動し直します

- **実行結果**：0.1.x のときと同じ声と速さで読みます
- **AivisSpeech Engine が動いているとき**：0.2.0 からは、初期の設定（`VOICE_REPLY_ENGINE` が `auto`）のままだと AivisSpeech の声で読みます。今までどおり OS の声で読ませたいときは、`VOICE_REPLY_ENGINE` を `os` にします

## 読み上げの時間の上限

声を出す処理（Mac の `say`、Windows の PowerShell、AivisSpeech Engine）だけが固まると、その読み上げが終わらず、ほかのタブの読み上げがいつまでも順番を待つことになります。これを防ぐため、読み上げに時間の上限を設けています。

- **上限の決まり方**：読む区切りの文字数と速さの設定から、読み終わるまでの時間を見積もり、その2.5倍に30秒を足した時間を上限にします。順番待ちの時間は数えません
- **区切り**：OS の声は、読む文章の全体が1つの区切りです。AivisSpeech の声は1文ずつで、その文の音声ができるのを待つ時間と、鳴らす時間の合計を見張ります（1文目は、エンジンへの最初の問い合わせから）。文ごとにするのは、音声を作る時間が読む時間より長い PC でも、固まった文にすぐ気づけるようにするためです
- **働くとき**：上限を超えたら、自分の声だけを止めて、次の読み上げに順番を渡します。初期の声なら、読むのに時間がかかる数字ばかりの文章でも見積もりの約2倍で読み終わるので、ふつうは上限に届きません。ほかの声にしているときなど、実際の読み上げが見積もりより遅いと、声が固まっていなくても途中で止まることがあります（「うまくいかないとき」を参照）
- **文章の長さ**：制限しません。長い文章ほど上限も長くなります
- **止めても声が終わらないとき**：止めてから2秒待っても読み上げが終わらなければ、待つのをやめて、次の読み上げに順番を渡します。同じタブの新しい返事で止めたときも同じです

初期の速さでの上限の例です。

| 声 | 読む区切り | 読み終わるまでの見積もり | 上限 |
| :- | :- | :- | :- |
| OS の声（Mac と Windows で同じ） | 400文字（要約くらい）の全体 | 50秒 | 2分35秒 |
| OS の声（Mac と Windows で同じ） | 4,000文字（長い返事の全文）の全体 | 8分20秒 | 21分20秒 |
| AivisSpeech | 40文字の1文 | 約5秒 | 約42秒 |
| AivisSpeech | 100文字（1文の最大）の1文 | 約12秒 | 約61秒 |

- **速さを変えたとき**：速くすると見積もりと上限が短くなり、遅くすると長くなります
- **Mac で `VOICE_REPLY_MAC_RATE` を `770` より大きくしたとき**：声はそれ以上速くならないので、`770` として見積もります
- **AivisSpeech の速さの見積もり**：speedScale と1秒に読む文字数の対応（0.8 で 5.00文字、1.0 で 6.09文字、1.2 で 7.08文字、1.5 で 8.50文字）を測り、その間は直線でつないで見積もります。0.8 より遅いときは 0.8 の値から speedScale に比例して下げ、1.5 より速いときは 1.5 の値で頭打ちにします。どちらも、実際より遅めに見積もる（上限が長くなる）向きです
- **見積もりの基準**：見積もりは、初期の声（Mac は Kyoko、Windows は Microsoft Haruka Desktop、AivisSpeech はまお（ノーマル））で測った速さを基にしています

## うまくいかないとき

| 困っていること | 確かめること |
| :- | :- |
| 読み上げない | `/voice-reply:toggle on` でオンにします。それでも読まないときは、`node` が PATH にあるか（Node.js 18 以上か）、「必要なもの」の声が入っているかを確かめます。`VOICE_REPLY_ENGINE` を `aivisspeech` にしているときは、エンジンが動いていないと読みません |
| 要約が付かず、全文を読む | `/clear` を実行するか、新しいセッションを始めます（要約の指示はセッションの始めに渡すため） |
| 2回ずつ読む | ほかにも読み上げのフックを入れていないか、`~/.claude/settings.json` の `hooks` を確かめます |
| 要約の指示が2重になる | `CLAUDE.md` などに、自分で書いた `<speak>` の要約の指示が残っていれば消します |
| 0.2.0 にしたら、声や速さの設定が効かない | 環境変数の名前が変わりました。「古い名前からの切り替え」のとおりに書き換えます |
| AivisSpeech Engine を起動しているのに、OS の声で読む | ブラウザで `http://127.0.0.1:10101/version` を開き、エンジンの版が表示されるかを確かめます。表示されないときは、エンジンがまだ起動の途中か（初めての起動では数分かかります）、ほかのポートで動いています。ほかのポートのときは `VOICE_REPLY_AIVIS_URL` を合わせます。`VOICE_REPLY_ENGINE` が `os` になっていないかも確かめます |
| AivisSpeech の声が途中で止まる | エンジンが途中で失敗すると、そこで読むのをやめます。エンジンのログ（「エンジンのデータと、読んだ文章の記録」を参照）にエラーが出ていないかを確かめます。時間の上限を超えたときも止まります |
| 長い読み上げが途中で止まる | 読み上げの時間の上限（「読み上げの時間の上限」を参照）を超えると止まります。`VOICE_REPLY_MAC_VOICE`・`VOICE_REPLY_WIN_VOICE`・`VOICE_REPLY_AIVIS_STYLE` でほかの声にしているときや、Windows で Haruka が入っておらずほかの声に切り替わっているときは、見積もりより遅く読んで上限に届くことがあります。初期の声に戻すと直ることがあります |

原因を調べるときは、`claude --debug` で起動します。debug ログで `voice-reply` を含む行を見ると、どのフックが動いたかが分かります。

## アンインストール

```text
/plugin uninstall voice-reply@mg1986jp
```

プラグインの画面が開くので、アンインストールします。ほかの場所（プロジェクトの設定など）に入れていなければ、プラグインのデータフォルダ（オン・オフの状態と、読み上げの順番待ちと AivisSpeech の音に使う一時ファイル）も消えます。

AivisSpeech Engine と、そのデータ（約 1.1 GiB）は、このプラグインとは別なので消えません。要らなければ、エンジン（または AivisSpeech）を消してから、データフォルダ（「エンジンのデータと、読んだ文章の記録」を参照）を消します。

## 仕組み

フックを3つ使います（`hooks/hooks.json`）。

| フック | スクリプト | 役割 |
| :- | :- | :- |
| SessionStart | `scripts/session-start.js` | 要約の指示（`prompts/speak.md`）を Claude に渡す。新しいセッション、再開、`/clear`、圧縮のたびに動く |
| UserPromptExpansion | `scripts/toggle.js` | `/voice-reply:toggle` を受けて、オン・オフを切り替える |
| Stop | `scripts/speak.js` | 返事を読み上げる（バックグラウンドで動く） |

| ファイル・フォルダ | 内容 |
| :- | :- |
| `prompts/speak.md` | Claude に渡す要約の指示。文章を直すときは、このファイルだけを直します |
| `scripts/lib/` | 読む文章を作る処理、文に分ける処理（`sentences.js`）、WAV を鳴らす処理（`wav-player.js`）、排他制御（差し替え・順番待ち）、読み上げの時間の上限、オン・オフの状態など |
| `scripts/voices/` | 声ごとの読み上げ処理（`mac-say.js`、`windows-sapi.js`、`aivisspeech.js`）と、速さの設定から1秒に読む文字数を見積もる処理。どの声で読むかは `index.js` で決めます。声を足すときは、ここにファイルを足して `index.js` で選べるようにします。1秒に読む文字数（`charsPerSecond()`）を持たない声では、時間の上限を設けません |
| `skills/toggle/` | `/voice-reply:toggle` コマンド |

状態と一時ファイルは、Claude Code がプラグインに用意するデータフォルダ（`~/.claude/plugins/data/` の下）に置きます。`tmp/` に読み上げの順番待ちのファイル、`audio/` に AivisSpeech の音の一時ファイルを置きます。

### 手元で試す

リポジトリを clone したフォルダを、`--plugin-dir` で読み込みます。

```text
claude --plugin-dir ./voice-reply
claude plugin validate ./voice-reply
```

1行目は、インストールせずにプラグインを読み込んで起動します。2行目は、プラグインとマーケットプレイスの設定を検証します。

テストは、clone したフォルダの中で次のように実行します。

```text
node --test test/*.test.js
```

- **必要なもの**：Node.js だけです。テストは Node の標準の機能（`node:test` と `node:assert`）だけで書いているので、npm パッケージを入れる必要はありません
- **実行結果**：すべてのテストが通ると、最後に `fail 0` と表示されます。待ち時間を確かめるテストがあるため、終わるまで20秒ほどかかります
- **声について**：テストでは本物の声も音も出しません。声を出す子プロセス（`say`、PowerShell、`afplay`）は偽物にし、Mac として動いていることにするテストもあるので、Windows でも Mac 向けの処理まで確かめられます
- **AivisSpeech Engine について**：テストでは、テストの中で動く偽のエンジンを使います。本物のエンジンが動いている PC でも、本物のエンジンにはつなぎません
