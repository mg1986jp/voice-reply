# voice-reply

Claude Code の返事を声で読み上げるプラグインです。OS 標準の声ですぐに使えます（Mac は `say`、Windows は SAPI の声）。

返事の最後に、耳で聞いて分かる短い要約（`<speak>〜</speak>`）を Claude に付けさせ、その要約を読み上げます。

## できること

- **返事の読み上げ**：Claude が返事を書き終えると、その返事を読み上げます。読み上げはバックグラウンドで動くので、読んでいる間も次の操作ができます
- **要約だけを読む**：返事の一番最後にある `<speak>〜</speak>` の中身だけを読みます。要約の書き方の指示は、このプラグインがセッションの始めに Claude に渡します
- **タブごとの交通整理**：同じタブで次の返事が来たら、今の読み上げを止めて新しい返事に差し替えます。別のタブの返事は、今の読み上げが終わるまで順番を待ちます（声が重なりません）
- **オン・オフ**：`/voice-reply:toggle` で読み上げを止めたり、再開したりできます

## 必要なもの

| もの | 内容 |
| :- | :- |
| Claude Code | v2.1.332 で動作を確認しています |
| Node.js | `node` コマンドが PATH から使えること。npm パッケージは使いません |
| Mac の声 | `say` コマンド（macOS に標準で入っています）と、日本語の声「Kyoko」。Kyoko が入っていないときは、システム設定の「アクセシビリティ」→「読み上げコンテンツ」で追加するか、`CLAUDE_SAY_VOICE` で入っている声を指定してください |
| Windows の声 | Windows PowerShell 5.1（Windows に標準で入っています）と、日本語の声「Microsoft Haruka Desktop」。Haruka が入っていないときは、入っている日本語の女性の声、なければ日本語の声に自動で切り替えます |

Mac と Windows 以外の OS では、読み上げは動きません。要約の指示も渡さず、何もせずに終わります。

## 入れ方

Claude Code のセッションで、次の2つを順に実行します。

```text
/plugin marketplace add mg1986jp/voice-reply
/plugin install voice-reply@mg1986jp
```

- 1行目で、このリポジトリをマーケットプレイス `mg1986jp` として登録します
- 2行目でプラグインの画面が開くので、インストールします。画面を閉じると、Claude Code がプラグインを読み込み直します
- **実行結果**：次の返事から読み上げが始まります
- **要約の指示について**：要約の指示はセッションの始めに渡すため、インストールした時点で開いていたセッションには届いていないことがあります。届いていないセッションでは、返事の全文（Markdown の記号を除いたもの）を読みます。要約を読ませたいときは、`/clear` を実行するか、新しいセッションを始めてください

## 使い方

入れたあとは、何もしなくても返事ごとに読み上げます。読み上げる文章は次のように決まります。

1. 最初に「（作業フォルダの名前）の作業です。」と読みます。どのタブの返事かを聞き分けるためです
2. 返事の一番最後に `<speak>〜</speak>` があれば、その中身を読みます
3. なければ、返事の全文を読みます。Markdown の記号は取り除き、コードは「コードは省略します。」、URL は「URLは省略します」と読みます

## オン・オフ

| コマンド | 実行結果 |
| :- | :- |
| `/voice-reply:toggle` | 今と逆にします（オンならオフ、オフならオン） |
| `/voice-reply:toggle on` | オンにします |
| `/voice-reply:toggle off` | オフにします |

- **オフのとき**：返事を読み上げません。新しいセッションを始めても、要約の指示を渡しません
- **切り替えたとき**：そのセッションの Claude にも、すぐに伝わります。オンにしたときは要約の指示を、オフにしたときは「要約は不要」と伝えます
- **状態の保存**：状態はすべてのタブで共通で、Claude Code を終了しても残ります。ほかのタブで開いているセッションの Claude には切り替えたことが伝わらないので、そのタブでは要約が付き続けたり（読み上げはされません）、付かなかったりします
- **読んでいる途中でオフにした場合**：その読み上げは最後まで続きます。次の返事から読み上げなくなります
- **順番待ちの読み上げ**：別のタブの読み上げが終わるのを待っている返事は、オフにすると読まれません。順番が来たときに、オンかオフかを確かめ直すためです

## 速さと声の変え方

環境変数で変えます。`~/.claude/settings.json` の `env` に書いておくと、いつも同じ設定で動きます。

```json
{
  "env": {
    "CLAUDE_SAY_RATE": "300",
    "CLAUDE_SAY_WIN_RATE": "5"
  }
}
```

| 環境変数 | 対象 | 内容 | 初期値 |
| :- | :- | :- | :- |
| `CLAUDE_SAY_RATE` | Mac | 速さ。`say -r` に渡す値（1分あたりの語数）で、正の整数 | `260` |
| `CLAUDE_SAY_WIN_RATE` | Windows | 速さ。System.Speech の Rate で、`-10`〜`10` の整数。`0` が標準の速さで、1増えるごとに約1.12倍になります | `3`（標準の約1.4倍） |
| `CLAUDE_SAY_VOICE` | Mac・Windows | 声の名前 | Mac は `Kyoko`、Windows は `Microsoft Haruka Desktop` |

- **決まりに合わない値**：範囲外の数や、数字でない文字を書いたときは、初期値で読みます。小数は切り捨てて使います（`250.7` は `250`）
- **反映されるタイミング**：`settings.json` を変えたら、Claude Code を起動し直すと確実に反映されます

## うまくいかないとき

| 困っていること | 確かめること |
| :- | :- |
| 読み上げない | `/voice-reply:toggle on` でオンにします。それでも読まないときは、`node` が PATH にあるか、「必要なもの」の声が入っているかを確かめます |
| 要約が付かず、全文を読む | `/clear` を実行するか、新しいセッションを始めます（要約の指示はセッションの始めに渡すため） |
| 2回ずつ読む | ほかにも読み上げのフックを入れていないか、`~/.claude/settings.json` の `hooks` を確かめます |
| 要約の指示が2重になる | `CLAUDE.md` などに、自分で書いた `<speak>` の要約の指示が残っていれば消します |

原因を調べるときは、`claude --debug` で起動します。debug ログで `voice-reply` を含む行を見ると、どのフックが動いたかが分かります。

## アンインストール

```text
/plugin uninstall voice-reply@mg1986jp
```

プラグインの画面が開くので、アンインストールします。ほかの場所（プロジェクトの設定など）に入れていなければ、プラグインのデータフォルダ（オン・オフの状態と、読み上げの順番待ちに使う一時ファイル）も消えます。

## 仕組み

フックを3つ使います（`hooks/hooks.json`）。

| フック | スクリプト | 役割 |
| :- | :- | :- |
| SessionStart | `scripts/session-start.js` | 要約の指示（`prompts/speak.md`）を Claude に渡す。新しいセッション、再開、`/clear`、圧縮のたびに動く |
| UserPromptExpansion | `scripts/toggle.js` | `/voice-reply:toggle` を受けて、オン・オフを切り替える |
| Stop | `scripts/speak.js` | 返事を読み上げる（バックグラウンドで動く） |

| ファイル・フォルダ | 内容 |
| :- | :- |
| `prompts/speak.md` | Claude に渡す要約の指示。文章を直すときは、このファイルだけを直します |
| `scripts/lib/` | 読む文章を作る処理、排他制御（差し替え・順番待ち）、オン・オフの状態など |
| `scripts/voices/` | 声ごとの読み上げ処理（`mac-say.js`、`windows-sapi.js`）。声を足すときは、ここにファイルを足して `index.js` で選べるようにします |
| `skills/toggle/` | `/voice-reply:toggle` コマンド |

状態と一時ファイルは、Claude Code がプラグインに用意するデータフォルダ（`~/.claude/plugins/data/` の下）に置きます。

### 手元で試す

リポジトリを clone したフォルダを、`--plugin-dir` で読み込みます。

```text
claude --plugin-dir ./voice-reply
claude plugin validate ./voice-reply
```

1行目は、インストールせずにプラグインを読み込んで起動します。2行目は、プラグインとマーケットプレイスの設定を検証します。

テストは、clone したフォルダの中で次のように実行します。

```text
node --test test/*.test.js
```

- **必要なもの**：Node.js だけです。テストは Node の標準の機能（`node:test` と `node:assert`）だけで書いているので、npm パッケージを入れる必要はありません
- **実行結果**：すべてのテストが通ると、最後に `fail 0` と表示されます。待ち時間を確かめるテストがあるため、終わるまで20秒ほどかかります
- **声について**：テストでは本物の声は出しません。Mac として動いていることにした偽の声を使うので、Windows でも Mac 向けの処理まで確かめられます
